# patcov — 代数数据类型模式的“覆盖见证”库

为离线语言工具提供的可复用 Python 模块。对模式匹配序列计算：

1. **每个分支按源顺序是否“有用”**（是否存在不被前面任何分支匹配、却被本
   分支匹配的值）；无用分支即**冗余分支**；
2. 有用分支的**最小见证值**；
3. 所有分支之后**整体遗漏值中的最小值**（穷尽时为 `None`）。

有两套并存的语言版本，由显式参数选择（旧调用默认走 v1，行为完全不变）：

| | **version=1（默认，旧契约）** | **version=2（本次扩展）** |
| --- | --- | --- |
| 类型 | Bool、枚举、积、有标签和；**非递归**，嵌套深度 ≤12 | 上述全部 + **递归/互递归** + **整数闭区间类型** |
| 模式 | 通配、构造器、积、or | 加**整数字面量/闭区间**、**绑定 `bind`**、**分支守卫 `when`** |
| 判定 | 精确（共享有序决策 DAG 的 Maranget） | 精确（有限模式矩阵状态图，**不按固定深度展开**） |
| 预算耗尽 | 抛 `CoverageBudgetExhausted` | 返回 `status="unknown"` + 未决状态，**不宣称穷尽** |
| 证书 | 无 | 成功时可选**覆盖证书**（有限状态闭合关系），独立检查器复核 |

- Python 版本：**Python 3.14.7**（CPython，Linux 原生）。
- 依赖：**仅标准库**；无需联网、数据库、容器、第三方 API、账号或密钥。

## 运行方式

在仓库根目录：

```bash
# 快速回归（v1 全部旧测试 + v2 核心语义/证书/边界，约 0.3 秒）
python -m unittest discover -s tests -v

# 扩展验证（大批量随机独立核对、深度参数族到 k=50、
# 8 种互递归类型/80 分支/±10^9 主规模，约 14 秒）
python -m unittest discover -s tests -p 'check_v2_extended.py' -v

# 固定输入演示（真实计算；约 0.1 秒，无 sleep、无预录结果）
python demo.py
```

两套测试分开：默认 discover 只匹配 `test*.py`，扩展文件名是
`check_v2_extended.py`，不会混进快速回归。

## 公开接口

```python
from patcov import analyze, verify_certificate, CoverageError

# v1（默认；旧行为逐字保留）
result = analyze(types, patterns, *, budget=50_000_000)

# v2：递归类型 + 整数闭区间 + 绑定 + 守卫（默认即提交覆盖证书；
# certificate=False 可关闭以节省内存）
result = analyze(types, patterns, *, version=2, budget=50_000_000)
# 独立检查器（不导入、不复用主搜索引擎与缓存）
summary = verify_certificate(types, patterns, result)
```

## v1 类型与模式（未变化）

类型为有序 `dict`，**第一项是根类型**：

```python
{"Bool": {"kind": "bool"}}                                  # 仅允许作为根首项
{"Color": {"kind": "enum", "constructors": ["Red", "Green", "Blue"]}}
{"Pair": {"kind": "product", "fields": [("a", "Bool"), ("b", "Color")]}}
{"Shape": {"kind": "sum", "variants": [
    ("Circle", [("r", "Bool")]), ("Dot", [])]}}
```

v1 模式：`"_"`、`"Red"`/`"True"`、`("Circle", p, ...)`、`[p, ...]`、
`("or", p1, ...)`。**v1 仍拒绝递归类型与整数类型**（错误信息不变）。

## v2 新增类型

```python
{"Score": {"kind": "integer", "range": [-10**9, 10**9]}}
```

- 闭区间两端都是**含端点**的 Python `int`（拒绝 `bool`；拒绝浮点）；
  绝对值工程上限 10^18，题面要求的 10^9 在范围内。
- 类型可以任意前向/互相引用并**递归**。构造器可递归，但所有类型声明先做
  **生产性检查（最小不动点）**：
  - integer/bool 可构造；
  - product 可构造 ⇔ 所有字段类型可构造；
  - enum/sum 可构造 ⇔ 至少一个构造器的全部字段类型可构造。
- **不可构造类型合法存在，值域为空**。例如
  `E = C(E)` 没有任何值：对它的任何匹配都穷尽（真空），匹配其构造器的
  分支判为冗余。结果证书的 `nonconstructive` 字段列出这些类型。

## v2 新增模式

| 写法 | 含义 |
| --- | --- |
| `5`（int 字面量） | 整数单点（拒绝 `bool`；须落在类型闭区间内） |
| `("range", a, b)` | 整数闭区间 [a, b]（含端点；与类型区间求交，无交集报错） |
| `("bind", "x", p)` | 绑定：`p` 匹配的值绑定到 `x`；对匹配透明 |
| `("or", p1, ...)` | 或模式（备选互不可见，语义同 v1） |
| `{"pattern": p, "when": g}` | 带守卫的分支（守卫也可省略为裸模式） |

Bool 模式仍是字符串 `"True"`/`"False"`（见证值仍是 Python `bool`）。

### or 的绑定一致性

同一 `or` 的每个备选必须绑定**相同名称集合、相同类型**，否则输入阶段拒绝
（可定位到具体备选）。绑定对守卫可见，守卫变量在内部按分支命名空间隔离。

### 守卫语言（只允许已绑定整数与常数比较）

```python
"true" / "false"
["<=", "x", 5]  ["<", ...] [">", ...] [">=", ...] ["==", ...] ["!=", ...]
["in", "x", [-3, 3]]                # 整数闭区间（含端点）
["and", g1, g2, ...] ["or", ...] ["not", g]
```

- 左侧必须是**本分支**绑定的整数变量；右侧必须是 `int` 常数（拒绝 `bool`
  与变量间比较、算术表达式）。守卫节点数有上限（200）。
- 守卫谓词全部是单变量一元条件，不存在跨变量耦合；求解器按相关区间端点
  把整数轴切成有限个极大段，段内每个守卫真值恒定，**按段而非按值枚举**。

## v2 见证次序

先比**构造器节点数**（bool/enum/sum 构造器计 1，product 与整数计 0），
再比**前序键**：构造器按输入声明次序编号；整数按绝对值升序，
**同绝对值时负数先于正数**：`0, -1, 1, -2, 2, -3, 3, ...`。

- 例：只覆盖 `{-1,0,1}` 时最小遗漏是 `-2`（不是 2）。
- 递归列表只匹配长度 `0..k-1` 时，最小遗漏是长度 `k` 的全 False 列表；
  见证深度完全由**输入模式**决定，引擎不内置任何深度阈值。

## v2 返回值 `V2Result`

| 属性 | 含义 |
| --- | --- |
| `status` | `"exhaustive"` / `"incomplete"` / `"unknown"` |
| `branches` | `V2BranchResult(index, useful, witness)` 元组；`useful` 为 True/False/None（未决） |
| `uncovered` | 题面序最小遗漏值；穷尽为 `None`；unknown 为 `None` |
| `exhaustive` | True/False；unknown 时为 `None`（三态，不用 False 冒充） |
| `redundant_branches` / `unknown_branches` | 冗余/未决分支下标 |
| `certificate` | 覆盖证书（`certificate=True` 时），否则 `None` |
| `pending` | unknown 时的未决有限状态（纯数据，含问题类型与列/行渲染） |
| `budget_used` / `budget` | 实际/预算工作量单位 |

## 覆盖证书与独立检查器

`certificate=True` 时成功结果带纯数据证书：

- 规范化类型声明、根类型、`nonconstructive` 列表；
- 结论与最小见证；
- **有限状态闭合关系**：根状态、全部可达状态、每状态后继（构造器分支 /
  整数段（段端点、新序代表值）/ 全通配弹出 / 自由终态 / 空值域终态 /
  单位终态）；
- 每个见证状态的最优（构造器节点数，前序键）。

`verify_certificate(types, patterns, result)` 用**完全独立的第二套引擎**
（普通 tuple 矩阵、独立 memo；不导入 `recsolver`，不读其缓存/闭合记录）
重新计算并核对：

1. 逐分支有用性、最小见证（独立匹配器做见证往返核对）；
2. 整体结论与最小遗漏；
3. 证书状态图与独立状态图同构、后继一致、整数段无重叠无缝隙覆盖整个类型
   闭区间、段代表为新序最小整数；
4. 每个见证状态满足局部最优（Bellman）方程。

检查器**不信任证书里的任何布尔标志**；篡改结论、见证或状态权值都会抛
`CertificateRejected`（demo 第 7 段与测试实演）。

## 错误语义

- 违反契约一律抛 `patcov.CoverageError`（`ValueError` 子类），信息带可定位
  路径（如 `patterns[2].when[1]: 守卫变量 'x' 未由本分支顶层 or 模式绑定`）。
- `analyze` 为纯函数；非法输入在产生结果前抛出。
- `budget`：普通 `int`，拒绝 `bool`/`float`（NaN/±∞ 因此一律拒绝），
  范围 [1, 2^63−1]。
- **预算耗尽 ≠ 证明穷尽**：
  - v1：抛 `CoverageBudgetExhausted`（`RuntimeError` 子类）；
  - v2：返回 `status="unknown"`、`exhaustive=None`、`pending` 列出未决状态；
    调大 `budget` 重试即可。小规模独立参考覆盖的用例永远给确定答案，
    `unknown` 不是“通用实现”。

### 输入上限

| 上限 | v1 | v2 |
| --- | --- | --- |
| 用户构造器总数 | 128 | 128 |
| 类型/模式语法嵌套深度 | 12 | 模式语法 1000（递归展开不受此限） |
| 单构造器字段数 | 10000 | 10000 |
| 整数端点/守卫常数绝对值 | — | 10^18（题面 10^9 在内） |
| 守卫节点数 / 顶层 or 绑定数 | — | 200 / 32 |
| 单分支模式节点数 | 1,000,000 | 1,000,000 |
| 支持规模 | — | ≥8 种递归类型、80 分支（扩展测试实测） |

## 设计要点

- **为什么递归可以完备**：问题状态是“模式矩阵 × 列类型序列”。每次特化
  消耗一个非通配模式头（构造器/区间），通配头只复制通配行、全通配列直接
  弹出，所以任一搜索路径上非通配头严格递减，状态图是**有限 DAG**——无需
  深度截断即可精确判定穷尽/遗漏（递归类型上的经典 Maranget 原理）。
- **整数不按值域穷举**：收集存活模式区间与守卫中相关变量的全部端点，切出
  有限个极大段；每段取新序最小整数为代表。规模只取决于区间/分支数，与
  10^9 的值域大小无关。
- **最优见证**：状态图上的加性最短路 DP（构造器节点数为权，前序键为平局
  序），每型最小值用两阶段不动点（先权值、再声明序）求出，避免 LFP 时序
  把“先就绪但声明序靠后”的构造器锁成最小值。
- **v1 引擎保持原样**：`solver.py` 一行未改其判定逻辑；v2 是独立的
  `recsolver.py`，两套记忆化与证书检查器三方互不共享缓存。

## 测试与正确性依据

- **v1 旧测试 50 个逐字保留**（未删、未放松断言），另加 v2 测试 39 个快速
  + 7 个扩展。
- 两套独立暴力参考（`tests/_reference.py`、`tests/_reference_v2.py`）自行
  解析类型、枚举小有限值域、独立实现匹配/守卫/字典序，**不导入被测核心**；
  快速套件与扩展套件（约 900 例随机）逐值一致。
- 递归无限值域由：结构性质（状态图有限、证书同构）、**深度参数类型族**
  （k=0..50 每个都给确定的长度 k 见证并通过独立闭合/Bellman 核对）、
  深层具体值分支共同保证；参考验证从不调用被测求解器算期望值。
- 覆盖 or 重复、跨字段关联、守卫布尔组合、相邻区间单点缺口、空递归/互递归
  空类型、or 绑定名/类型冲突、未绑定守卫变量、bool 冒充整数、预算 unknown、
  证书篡改必拒等边界。

## 与旧版的差异与迁移

| 变化 | 影响 | 迁移 |
| --- | --- | --- |
| `analyze` 新增仅关键字参数 `version`（默认 1）、`certificate`（默认 False） | 旧调用无需任何修改，返回类型/异常/确定性不变 | 不需要迁移 |
| v2 支持递归类型（v1 仍拒绝） | 仅 `version=2` | 需要递归/整数时显式传 `version=2` |
| v2 整数类型/字面量/区间/绑定/守卫 | 仅 `version=2`；v1 遇到这些写法仍报可定位错误 | 同上 |
| v2 预算耗尽不抛异常而返回 unknown | 仅 `version=2`；v1 仍是 `CoverageBudgetExhausted` | v2 调用方检查 `status=="unknown"` 与 `pending` |
| v2 返回 `V2Result`（三态 `exhaustive`），不是 `AnalysisResult` | 仅 `version=2` | 用 `status`/`exhaustive is None` 区分未决 |

## 已知限制

- 守卫只支持“已绑定整数变量 vs 常数”的比较/区间与布尔组合；无字符串/浮点
  字面量、无算术、无变量间比较、无跨变量耦合（这是逐列精确分段可判定的
  边界）。
- 整数类型必须给出有限闭区间；不支持无界整数（端点上限 10^18）。
- 不做类型推断/语言集成；类型与模式按本模块字面结构给定。
- 结果为精确离散判定，不涉及浮点，无浮点误差口径。
