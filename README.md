# 代数数据类型模式的覆盖见证（Coverage Witness）

为离线语言工具提供的可复用模块：给定一组**有限、非递归代数数据类型**和一组按源顺序排列的
匹配分支（通配 / 构造器 / or，无 guard），计算

1. 每个分支相对之前分支是否**还有可匹配的新值**（是否冗余），并给出该分支新覆盖值中的
   **字典序最小见证**；
2. 整个匹配之后**整体遗漏**的字典序最小值。

核心使用**模式矩阵分解（Maranget 风格的 specialize / default 矩阵 + 有用列选择）与共享
决策结构**，从不枚举取值空间，也不展开完整笛卡尔积。构造器次序与字段次序完全由输入给定。

## 运行环境

- Python **3.14.7**，**仅使用标准库**（核心只依赖 Python 内置类型，无任何第三方包）。
- Linux 原生运行。安装 Python 后**无需安装其他依赖**，无需网络、账号、密钥、数据库、
  中间件、云 API 或 Docker。核心、测试、演示全部离线、确定性。

## 准确命令

```bash
# 测试（必要测试，含独立枚举预言机核对与确定性随机差分）
python -m unittest discover -s tests -v

```

```python
from coverage_witness import analyze

result = analyze(types, patterns, root="Box")
```

## 公开数据结构与接口

### 类型 `types: dict[str, dict]`

内建 `bool` 无需声明，构造器次序固定为 `False < True`。

| 种类 | 写法 |
|---|---|
| 枚举 | `{"kind":"enum","constructors":["R","G","B"]}` |
| 积   | `{"kind":"product","fields":[["x","Color"],["y","bool"]]}`（单一匿名构造器） |
| 有标签的和 | `{"kind":"sum","constructors":[["Point",[]],["Circle",[["r","bool"]]]]}` |

- 字段可写成类型引用字符串，或 `[字段名, 类型引用]`；字段名仅用于校验重名。
- 构造器、字段的**输入次序**即字典序次序。
- 类型名不可为 `bool`（保留）。

### 模式 `patterns: list`

- 通配：`{"kind":"wildcard"}`
- 构造器：`{"kind":"ctor","name":"C","fields":[...]}`
  - 积类型省略 `name`；无参构造器省略或给空 `fields`。
  - `bool` 构造器名为 `"True"`/`"False"`，也接受裸 Python 布尔 `True`/`False`。
- 或：`{"kind":"or","patterns":[...]}`（非空；允许重复、允许嵌套、可出现在字段中）。

### 见证值的表示（JSON 风格）

- bool：`True` / `False`
- 枚举：构造器名字符串，如 `"R"`
- 和：单键对象 `{"C": [字段值...]}`，无参为 `{"Point": []}`
- 积：列表 `[字段值...]`，零字段积（单位类型）为 `[]`

### `analyze(types, patterns, root=None, *, budget=1_000_000)`

- `root`：被匹配的顶层类型名。`types` 恰好一个类型时可省略；否则必须显式给出。
- `budget`：矩阵搜索节点预算，正整数。返回：

```python
{
  "root": "Box",
  "branches": [
    {"index": 0, "useful": True,  "redundant": False, "witness": {...}},
    {"index": 1, "useful": False, "redundant": True,  "witness": None},
    ...
  ],
  "exhaustive": False,
  "uncovered": {"Full": ["Maybe"]},   # 整体遗漏的字典序最小值；穷举时为 None
}
```

- 分支按源顺序，仅与此前**有用**分支比较；冗余分支不加入上下文（不会掩盖后续值）。
- 穷举时 `uncovered is None` 且 `exhaustive is True`。

### 错误语义（先固定，非法输入不静默纠正）

- `CoverageError(ValueError)`：契约违例。消息始终带可定位路径，如
  `patterns[2].fields[0]: unknown constructor 'X' for type 'Color'`。包括：未知构造器/类型、
  字段数不符、构造器/字段重名、递归类型、超过上限、or 无分支、布尔简写用于非 bool 类型等。
- `BudgetExhausted(RuntimeError)`：搜索预算耗尽，结论为**未定**。它与“证明穷举”严格分离：
  穷举是正常返回 `uncovered=None`，绝不以异常代替；预算不足时绝不谎称穷举。
- **数值**：本子集无数值域，任何 `float` 都拒绝；`NaN` 与 `±Infinity` 给出专门报错。
- `budget` 等整数参数**拒绝 `bool`**（`True`/`False` 不作为整数），且必须为正整数。
- 输入校验在任何计算前完成；`analyze` 无状态、无部分变更（纯函数，不修改入参）。

## 输入上限（接口边界）

- 全部用户声明的构造器总数 **≤ 128**（内建 `bool` 不计入）。
- 类型嵌套深度 **≤ 12**（深度按“构造器/积层数”计）。
- 递归类型一律拒绝（题目限定非递归）。
- 搜索节点默认预算 `1_000_000`，可用 `budget=` 调整。

这些是**接口边界**，不是短演示需要穷举的规模；演示只用很小的类型和一个 2^40 的 Bool 积。

## 算法与设计取舍

- **模式矩阵分解**：维护一个“已有用分支”矩阵与一个查询向量。每步选择有用列
  （查询为构造器的列优先，其次查询为 or，再其次矩阵中出现构造器的列），按该列构造器做
  specialize；若所有列头都是通配，则 default 丢弃一列。矩阵变空时直接构造最小见证，
  零列且仍有行时判定被覆盖。因此分支因子是**构造器个数**而非值个数。
- **共享决策结构**：所有分支共用同一棵被特化的矩阵；通配行在特化时生成通配子列，
  多个构造器分支共享前缀约束，天然避免笛卡尔积展开。
- **or 模式**：按子句做析取范式展开（有界，随子句大小增长），查询遇到 or 时分别求见证并
  取字典序最小；不与取值空间笛卡尔展开混同。
- **最小见证**：特化时按构造器声明次序递归，字段从左到右，全部取最小可行值，故得到的就是
  字典序最小未覆盖值；见证重组装严格对齐列位置。
- 预算按递归矩阵节点计数，使“搜了多少”可度量、可与“证明无解（穷举）”区分。

## 测试策略

`tests/test_coverage.py` 内含一个**完全独立的朴素参考实现**：直接从原始类型字典枚举小类型
全部取值、独立解释原始模式匹配，**不调用被测核心**。被测结果（每分支有用性、最小见证、
整体遗漏及次序）与该预言机逐项比对；“见证确实/不被匹配”的往返校验仅作补充。

- 小类型穷举核对（bool、枚举、积、和、嵌套）；
- or 重复（顶层与字段内）、积类型局部覆盖、永不匹配构造器；
- 巨大 Bool 积（2^20 穷举判定、2^100 压力，验证不展开）；
- 构造器/字段次序、错误语义、预算与穷举分离；
- 300 个固定种子随机差分用例（随机小型 ADT + 含 or 子句）。

## 已知限制 / 不宣称的内容

- 仅实现本题契约的有限数学子集：**非递归**、无函数类型、无无限类型、无 guard、
  无嵌套模式别名、无字面量数值模式（bool 除外）。不宣称兼容任何完整行业标准（如某语言完整
  模式匹配规范）。
- 不产生浮点结果，因此无误差/容差口径可言；任何浮点输入直接拒绝（不用容差掩盖边界）。
- 极小 `budget` 会对本可判定的问题抛 `BudgetExhausted`（“未定”），这是预期语义而非错误结果。
- 极端病态的超大多层 or 子句受节点预算约束；常规规模下默认预算充足。
