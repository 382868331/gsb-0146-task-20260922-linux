# patcov — 代数数据类型模式的“覆盖见证”库

为离线语言工具提供的可复用 Python 模块。对**有限、非递归**代数数据类型上的
模式匹配序列，计算：

1. **每个分支按源顺序是否“有用”**：是否存在一个值，不被它前面的任何分支匹配、
   却被本分支匹配。无用的分支即**冗余（永不匹配）分支**；
2. 有用分支的**字典序最小见证值**；
3. **每个分支实际首个命中的输入种数**（精确计数，非抽样估计）；
4. 所有分支之后的**遗漏值种数**与遗漏值中的字典序最小值（穷举时为 `None`）。

分支按书写顺序匹配：同一个值即使符合多个模式，也只计入**最先命中**的分支。
因此恒有可核对的恒等式：

```
sum(branch_counts) + uncovered_count == total_count
```

计数为 **Python 任意精度整数的纯符号运算**：宽记录（例如 500 个 Bool 的积，
值域 2^500）也只做 O(字段数) 次大整数加减乘，**绝不逐值展开笛卡尔积**。

核心算法是**共享有序决策 DAG 上的 Maranget 有用性子句**，**不展开任何值域
笛卡尔积**：例如 n 个 Bool 的积产生 O(n) 的处理量，而绝不是 2^n。

- Python 版本：**Python 3.14.7**（CPython，Linux 原生）。
- 依赖：**仅标准库**；安装 Python 后无需安装任何其他依赖。
- 完全离线：不需要网络、账号、密钥、数据库、中间件、云 API 或 Docker。

## 运行方式

在仓库根目录（本 README 所在目录）：

```bash
# 执行必要测试（独立暴力参考在小类型上核对，不调用被测核心）
python -m unittest discover -s tests -v

# 固定输入演示：真实计算正常结果 + 实际触发拒绝边界与预算耗尽边界
python demo.py
```

`demo.py` 在约 8 秒内完成（实测约 0.05 秒），不使用 sleep、不使用预录结果。

## 公开接口

```python
from patcov import analyze, CoverageError, CoverageBudgetExhausted

result = analyze(types, patterns, *, budget=50_000_000)
```

### 类型声明 `types`

有序 `dict`（用普通 `dict` 字面量即可，Python 保留插入顺序），**第一项是被测
（scrutinee）根类型**。支持四种类型：

```python
# 内置 Bool（永远可用，构造器按次序 False=0, True=1）
{"Bool": {"kind": "bool"}}            # 仅允许作为首项（根）直接声明

# 枚举：零元构造器，次序由输入列表给定
{"Color": {"kind": "enum", "constructors": ["Red", "Green", "Blue"]}}

# 积：命名字段（字段次序由输入给定）
{"Pair": {"kind": "product",
          "fields": [("a", "Bool"), ("b", "Color")]}}

# 有标签的和：变体可带零或多个命名字段（变体与字段次序由输入给定）
{"Shape": {"kind": "sum", "variants": [
    ("Circle", [("r", "Bool")]),
    ("Rect",   [("w", "Bool"), ("h", "Bool")]),
    ("Dot",    []),
]}}
```

- 类型可前向/互相引用，但**必须非递归**（递归类型在输入校验时被拒绝）。
- 除根位置的 `{"Bool": {"kind": "bool"}}` 外，不得重声明内置 `Bool`，
  用户类型也不得使用 `kind: "bool"`。

### 模式 `patterns`

按源顺序排列的分支列表（源顺序即匹配优先级）。每个模式针对根类型：

| 写法 | 含义 |
| --- | --- |
| `"_"` | 通配 |
| `"Red"` / `"Dot"` | 零元构造器（Bool 用 `"True"` / `"False"`） |
| `("Circle", p1, ..., pn)` | 构造器模式（含 Bool 字段模式） |
| `[p1, ..., pn]` | 积（元组）模式，字段数须与 product 相符 |
| `("or", p1, ..., pn)` | 或模式，**允许重复备选**（语义为集合求并，天然幂等） |

无 guard。或模式的各备选在判定该分支有用性时**互不可见**（备选之间不互为
“前面的分支”），这是标准语义；重复备选不产生额外影响。

### 见证值形态

- Bool：Python `bool`（`False`/`True`）；
- 枚举、零元变体：标签字符串，如 `"Red"`；
- 积：`tuple`，如 `(False, "Red")`；
- 带字段变体：`(标签, 字段值...)`，如 `("Rect", False, True)`。

### 返回值 `AnalysisResult`

| 属性 | 含义 |
| --- | --- |
| `branches` | `tuple[BranchResult]`，与输入等长、同源顺序 |
| `branch_counts` | 各分支首个命中值的精确数量（`tuple[int]`，冗余分支为 0） |
| `covered_count` | 至少被一个分支处理的值总数（= `sum(branch_counts)`，因首命中互斥） |
| `uncovered_count` | 未被任何分支处理的值的精确数量（穷举时为 0） |
| `total_count` | 根类型全部可能值的精确数量（大整数） |
| `uncovered` | 整体字典序最小遗漏值；穷举时为 `None` |
| `exhaustive` | 是否穷举（等价于 `uncovered is None`） |
| `redundant_branches` | 冗余分支下标 tuple |
| `budget_used` / `budget` | 实际/预算工作量单位 |

`BranchResult`：`index`、`useful`（bool）、`witness`（有用时为最小见证，
否则 `None`）、`count`（该分支首个命中值的精确数量，冗余为 0，
且 `count > 0` 当且仅当 `useful`）、`redundant`（等价 `not useful`）。

### 字典序口径

先比较**构造器输入次序编号**（小者在前；Bool 为 `False < True`），构造器
相同再按**字段输入次序**逐字段拼接比较。因此构造器编号最靠小的构造器一旦存在
未覆盖值，其见证一定排在更靠后的构造器之前。

### 错误语义

- 所有违反契约的输入抛 `patcov.CoverageError`（`ValueError` 子类），错误信息带
  **可定位路径**，如 `patterns[2][1]: 构造器 'X' 需要 1 个字段模式，得到 0 个`。
  不做静默纠正。
- `analyze` 为纯函数，无模块级可变分析状态；非法输入在产生任何结果前即抛出，
  不存在“部分变更”。
- `budget` 必须是普通 Python `int`：
  - **拒绝 `bool`**（`True`/`False`，即使它是 `int` 子类）；
  - 拒绝 `float`，因此 **NaN / ±Infinity 一律被拒绝**（不是数值比较，而是类型拒绝）；
  - 取值范围 `[1, 2^63-1]`。
- **预算耗尽与“证明无解（穷举）”严格分开**：
  - 预算耗尽抛 `CoverageBudgetExhausted`（`RuntimeError` 子类），表示“在预算内
    未能得出结论”，**绝不表示已穷举**；可调大 `budget` 重试；
  - 真正穷举时正常返回，且 `result.uncovered is None`、`exhaustive is True`。

### 输入上限（接口边界）

| 上限 | 值 | 说明 |
| --- | --- | --- |
| 用户构造器总数 | **128** | 不含内置 Bool 的 2 个 |
| 类型/模式嵌套深度 | **12** | 根为第 1 层，逐层 +1 |
| 单个构造器/product 字段数 | **10000** | 受 CPython 原生递归栈约束的工程边界；超限可定位报错 |
| 单分支模式节点数 | 1,000,000 | 主要约束宽积的显式字段模式 |
| `budget` | 1 .. 2^63−1 | 工作量单位 |

短演示不必穷举上述上限规模。

## 设计取舍

- **为什么不用“逐列覆盖”**：把每行压成单列覆盖会丢失行内跨字段关联。例如
  `(True, _)` 与 `(_, True)` 并不覆盖 `(False, False)`。因此覆盖集用一棵按值树
  前序分支的**有序决策图**精确表示“模式矩形之并”。
- **共享与记忆化**：决策节点、类型/模式/见证序列全部 hash-cons 为整数 id，
  相同结构只存一份；`加入覆盖` 与 `有用性` 均记忆化。通配不直接当作全集，而是
  按构造器惰性展开（规模只与类型树大小成比例），从而保留后续兄弟位置的行内约束。
- **不展开笛卡尔积**：宽 Bool 积的位置序列用持久链表表示，每层下降为常数次
  共享操作；实测 10,000 个 Bool 字段的分析约 0.1–0.3 秒，工作量约 5×字段数（线性）。
- **精确计数**：在同一决策 DAG 上另有两个记忆化计数函数。`count_free(node, sig)`
  统计未覆盖数——分支节点按构造器求子节点未覆盖数之和；
  `count_match(node, sig, q)` 统计“被模式 q 匹配且未覆盖”的数——构造器分支
  求和、字段序列做积，or 不做容斥展开，而是把已处理备选顺序并入覆盖集，
  每个备选只计入其新增量（天然互斥、不重不漏）。所有运算为 Python 大整数，
  500 个 Bool 的积同样线性完成，结果可与 `total_count` 逐项核对。
- **最小见证**：有用性按构造器输入次序、字段输入次序搜索，首个成功组合即字典序
  最小；或模式在各备选见证中取字典序最小者。
- **预算口径**：`budget` 计量内部“工作步”（记忆化的 add/useful 展开次数），
  是确定的、与机器速度无关的搜索规模度量，而非墙钟时间；默认 5×10^7 对题面
  上限内输入足够。

## 测试与正确性依据

- 小类型手工核对（Bool、枚举、积、和、嵌套）。
- **独立暴力参考** `tests/_reference.py`：自行解析类型、显式枚举整个有限值域、
  独立实现匹配与字典序，逐值给出期望；它**不导入也不调用** patcov 的核心模块。
  测试在多种类型与数万随机模式（含重复备选的 or）上与参考逐值一致。
- “见证确实未被前序分支匹配且被本分支匹配”的往返性质仅作为**补充**校验。
- 覆盖 or 重复、积类型局部覆盖、跨字段不可塌缩、永不匹配构造器、巨大 Bool 积、
  深度/构造器/字段数上限、递归类型拒绝、NaN/Infinity/bool 参数拒绝、
  预算耗尽≠穷举、各分支精确计数与总数恒等式核对（含 2^500 大整数）等边界。

## 已知限制（按本题契约，不宣称完整行业标准兼容）

- 只支持有限、**非递归**类型；递归类型在输入阶段被拒绝。
- 模式只含通配、构造器、积、or；**无 guard、无字面量整数/字符串/区间模式、
  无别名/as、无嵌套异常或惰性模式**等行业语言特性。
- 不做类型推断/类型检查器集成：类型与模式均按本模块的字面量结构给定。
- 算法为 CPython 原生递归实现，字段宽度设有明确上限（10000），上限内保证不触发
  `RecursionError`；超过上限会得到可定位的 `CoverageError` 而非栈崩溃。
- 结果为精确离散判定，**不涉及浮点计算**，因此不存在浮点误差/容差口径问题。
